# 项目立项与需求范围（Proposal）

## 1. 项目背景与目标
本项目对应课程「方向01：自然语言处理（NLP）综合作业」，旨在构建一个面向**中文医疗健康领域**的特定领域 RAG 问答系统（Domain-Specific QA）。

项目采用**「MVP 优先跑通 → 分阶段量化迭代」**的策略：先基于 CMedQA 数据集、DeepSeek 云端 API、本地轻量中文 Embedding 与轻量 Gradio 快速打通端到端闭环，再逐步完成检索强化、本地开源模型接入与 LoRA/SFT 微调，以及 FastAPI 服务化升级。

---

## 2. 需求范围（In Scope）

1. **领域知识库与数据体系**
   - 基于公开中文医疗数据集 **CMedQA（`cMedQA2`）**，清洗并构建 **≥ 5,000 条**高质量知识库语料。
   - 严格划分「知识库语料」「独立领域问答评测集」「拒答/域外测试集」，避免评测泄漏。
2. **核心问答能力**
   - **多轮对话**：支持历史上下文维护与连续追问（V1 引入 Query 改写/指代消解）。
   - **长上下文支持**：端到端支持 `>32k tokens` 输入，并具备专项压力测试验证。
   - **可解释引用来源**：回答附带引用编号（如 `[1]`、`[2]`），可溯源至原始文档片段与元信息。
   - **不确定性拒答与安全提示**：无依据或非医疗域外问题主动拒答，回答附医疗免责声明。
3. **演进与优化能力**
   - **模型路线**：DeepSeek 云端 API（MVP）→ 本地部署开源模型（如 Qwen2.5）+ LoRA/SFT 微调。
   - **检索路线**：单路本地语义检索 → Embedding 升级/云端对比 → BM25 + Dense 混合检索 + Reranker 重排。
   - **服务路线**：轻量 `Gradio` Demo（MVP）→ `FastAPI` 服务化部署（支持流式输出）。
4. **量化评测与交付物**
   - 在固定评测集上持续对比各版本（V0–V4）的**准确率、引用 F1、幻觉率**（及拒答率、召回率、延迟等辅助指标）。
   - 交付可复现全流程脚本、`README.md`、对比图表与实验报告。

---

## 3. 非目标（Out of Scope）

- 不提供真实临床诊疗建议或处方决策，仅定位为健康科普与学术研究原型。
- MVP 阶段不追求复杂前端视觉定制、多用户权限系统、高并发分布式集群。
- 不涉及医学影像、化验单 OCR 等多模态输入处理。
- 不将原始大体积数据集、本地向量索引或模型权重文件直接提交至 Git 仓库。

---

## 4. 成功标准（Success Criteria）

| 阶段 | 成功判定标准 |
| :--- | :--- |
| **MVP（V0）** | 知识库 ≥5,000 条可一键复现建库；DeepSeek + Gradio 端到端多轮问答/引用/拒答可用；产出 V0 Baseline 指标（准确率、引用 F1、幻觉率）并推送首次课程 PR。 |
| **进阶迭代（V1–V3）** | 通过 `>32k tokens` 长上下文测试；多轮 Query 改写、混合检索+重排、本地微调模型依次落地；每轮迭代在固定评测集上留存可对比的量化提升记录。 |
| **最终交付（V4）** | 完成 FastAPI 升级；全套脚本（数据、微调、推理、评估、部署）可独立复现；按规范交付实验报告（含对比表格、曲线与 Demo 截图/链接）并完成最终课程 PR。 |

---

## 5. 硬性约束条件

- **课程提交约束**：
  - 报告文件命名：`学号-姓名-01-NLP.md`（推荐）或 `学号-姓名-01-NLP.pdf`（附录可加后缀）。
  - 报告必备章节：项目概述、数据来源与处理、方法、实验结果（表格+曲线）、问题分析与创新点、Demo 截图/链接、未来改进方向。
  - PR 标题格式：`[作业01-NLP] 学号 姓名 - 领域特定RAG问答系统`，并完整填写 `.github/pull_request_template.md`。
  - 过程性评分：课程结束前持续通过 Commit / PR 更新，按更新记录体现阶段性能力提升。
- **团队协作约束**：日常开发基于小组 Fork 仓库（`https://github.com/zhang040705/LLM-Course.git`）分支协作，定期同步更新至老师仓库（`https://github.com/CAI-testbooks/LLM-Course.git`）。
- **成本与算力约束**：MVP 阶段优先使用本地轻量中文 Embedding 避免云端免费额度耗尽，同时合理控制 DeepSeek API 批量评测开销。
